# RepoDoctor — комплект заданий для четырёх агентов

Это **проектная документация для реализации**, а не готовое приложение. Исходного кода, lock-файлов и результатов запуска пока нет.

RepoDoctor помогает разобраться в чужом публичном GitHub-репозитории: изучает структуру, README и зависимости, составляет инструкцию запуска, отмечает возможные проблемы и разбирает вставленный лог ошибки.

## Как начать

1. Всем четырём агентам передать [ARCHITECTURE.md](ARCHITECTURE.md) и [ROADMAP.md](ROADMAP.md).
2. Каждому передать только его руководство из таблицы ниже. Не запускать сразу все задачи внутри руководства: выполнять по порядку, соблюдая входные условия.
3. Агент 1 выполняет `A1` — каркас и контракты. До завершения `G0` остальные могут готовить тестовые сценарии и локальные наброски, но не придумывают собственные API.
4. После `G0` агенты 2, 3 и 4 независимо реализуют свои модули на согласованных интерфейсах; агент 1 собирает backend.
5. На `G1` объединить рабочий offline-срез, на `G2` проверить live GitHub и AI, на `G3` провести репетицию защиты.

| Агент | Ответственность | Подробное руководство |
|---|---|---|
| 1 | Архитектор, backend, контракты, сборка, CI | [AGENT_1_PLATFORM.md](agents/AGENT_1_PLATFORM.md) |
| 2 | GitHub, снимок репозитория, парсеры, статические проверки | [AGENT_2_REPOSITORY.md](agents/AGENT_2_REPOSITORY.md) |
| 3 | AI, инструкция запуска, диагностика лога, fallback | [AGENT_3_AI.md](agents/AGENT_3_AI.md) |
| 4 | Интерфейс, UX, браузерные проверки, демонстрация | [AGENT_4_FRONTEND.md](agents/AGENT_4_FRONTEND.md) |

## Ключевые решения

- Python 3.12 + FastAPI; React + TypeScript + Vite; обычный CSS.
- Публичные репозитории GitHub; приоритет качественной поддержки Python и npm-проектов.
- Чтение файлов через GitHub REST API; код анализируемого проекта не исполняется.
- Один backend-процесс, синхронный HTTP-сценарий с ограниченными таймаутами; без очереди, Redis и базы данных.
- Детерминированные правила + один структурированный AI-ответ на операцию.
- Отдельные явные режимы `live` и `fixture`; демонстрационный ответ не выдаётся за результат реального анализа.
- Инструкция — обоснованный план, а не обещание успешного запуска. Приложение не проверяет команды исполнением.

Технические источники и ограничения находятся в конце [архитектуры](ARCHITECTURE.md). Версии зависимостей окончательно фиксирует агент 1 в `G0` после установки и smoke-проверки; frontend-lock принадлежит агенту 4.
